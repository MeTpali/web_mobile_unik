# Лабораторная работа № 1 · Вариант 6

Полный показ лабораторной по заданию 2026 года, включая Flutter-клиент: [../DEMONSTRATION.md](../DEMONSTRATION.md).

Подробный учебный разбор технологий, файлов и сценария защиты: [EXPLANATION.md](EXPLANATION.md).

Генератор случайных чисел. Выполнены этапы 1–5: основа React + Vite + Express, серверный API, форма с асинхронной генерацией и адаптивное оформление.

## Окружение

Проверено на Windows: Node.js **24.13.0**, npm **11.6.2**. Проект рассчитан на Node.js 24 версии не ниже 24.13.0. Для зависимостей используются точные версии и `package-lock.json`.

Выбраны React / React DOM 19.3.0, Express 5.2.1, Vite 8.3.1 и React-плагин 6.1.1. Установленный Node.js соответствует требованиям этих инструментов. См. [документацию Vite](https://vite.dev/guide/) и [Express](https://expressjs.com/en/starter/installing/).

Команды ниже выполняются в PowerShell из папки `lab-01`. Используется `npm.cmd`, чтобы политика PowerShell не блокировала `npm.ps1`.

## Установка

При первом запуске из основной папки курса:

```powershell
cd lab-01
npm.cmd ci
```

После установки зависимостей повторять `npm.cmd ci` перед каждым запуском не нужно.

## Разработка

В первом терминале, в папке `lab-01`:

```powershell
npm.cmd run dev:server
```

Во втором терминале, также в `lab-01`:

```powershell
npm.cmd run dev:client
```

Открыть **http://127.0.0.1:5173**. Ввести минимум и максимум, затем нажать «Сгенерировать» или Enter. Начальный диапазон — 1–100. Сервер автоматически перезапускается при изменении серверных файлов; Vite обновляет клиент.

Диагностика сервера: http://127.0.0.1:3000/api/health. Проверка proxy: http://127.0.0.1:5173/api/health. Оба адреса должны вернуть `{"status":"ok"}`.

Порты разработки: API — 3000, Vite — 5173. При занятом порте Vite сообщает об ошибке, не выбирая другой порт автоматически. Для остановки каждого процесса нажать Ctrl+C в соответствующем терминале.

## Сборка и запуск одним сервером

Остановить сервер разработки на порту 3000, затем выполнить:

```powershell
npm.cmd run build
npm.cmd start
```

Открыть **http://localhost:3000**. Express раздаёт сборку из `dist`; Vite в этом режиме не нужен. После изменения клиентского кода сборку следует повторить. До первой сборки страница на порту 3000 отсутствует, но диагностический API работает.

Сервер слушает `0.0.0.0`. Для подключения телефона позже потребуется открыть `http://<IPv4-адрес-ПК>:3000` в общей локальной сети и при необходимости разрешить входящие подключения в брандмауэре. Проверка сети и телефона пока не выполнена.

При необходимости порт Express можно изменить для текущего терминала:

```powershell
$env:PORT = '3001'
npm.cmd start
```

В режиме разработки proxy в `vite.config.js` настроен на порт 3000; при изменении серверного порта его нужно изменить и там. Чтобы вернуть порт по умолчанию в текущем терминале: `Remove-Item Env:PORT`.

## API генерации (этап 3)

`POST /api/random`, `Content-Type: application/json`. Тело: `{"min":1,"max":100}`. Ответ: `{"min":1,"max":100,"value":42}` (число может быть другим).

Обе границы включены. Допускаются целые числа от −1 000 000 000 до 1 000 000 000. Одинаковые границы возвращают единственное число. Строки, дроби, отсутствующие значения и обратный порядок границ отклоняются. Повторение результатов допустимо.

После запуска сервера пример запроса в PowerShell:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:3000/api/random -ContentType 'application/json' -Body '{"min":1,"max":100}'
```

Ошибки возвращаются в формате `{"error":{"code":"INVALID_RANGE","message":"..."}}`:

| Статус | Код                    | Причина                                                     |
| ------ | ---------------------- | ----------------------------------------------------------- |
| 400    | INVALID_RANGE          | Неверные поля или диапазон                                  |
| 400    | INVALID_JSON           | Повреждённый JSON                                           |
| 413    | PAYLOAD_TOO_LARGE      | Тело больше 1 КБ                                            |
| 415    | UNSUPPORTED_MEDIA_TYPE | Неверный Content-Type или неподдерживаемая кодировка        |
| 404    | NOT_FOUND              | Неизвестный API-маршрут                                     |
| 500    | INTERNAL_ERROR         | Непредвиденная ошибка; подробности только в консоли сервера |

Проверки сервера:

```powershell
npm.cmd test
```

Пройдены 6 тестов, включающих проверки генерации в положительном, отрицательном и полном диапазонах, одинаковых границ, некорректного ввода, HTTP-ответов, повреждённого JSON, размера тела, типа содержимого и неизвестного маршрута. HTTP-тесты самостоятельно запускают сервер на свободном локальном порту и останавливают его после проверки.

## Клиентская форма (этап 4)

Поля проверяются до отправки запроса: пустые значения, дроби, выход за пределы и обратный диапазон сопровождаются сообщением. Пока запрос выполняется, поля и кнопка заблокированы. При изменении границ предыдущий результат и ошибка очищаются.

Клиент обращается по относительному адресу `/api/random`, проверяет HTTP-статус, JSON и соответствие результата запрошенному диапазону. Ошибка сервера, отсутствие связи и превышение 10 секунд ожидания отображаются в форме. После завершения запроса, включая ошибку, ввод снова доступен.

Проверено на этапе 4:

- Сборка Vite проходит.
- Все 10 тестов сервера и клиентского API проходят, включая HTTP-ошибки, неверный ответ, отсутствие связи и отмену запроса по тайм-ауту.
- В Chrome в фоновом режиме проверены отправка кнопкой и Enter, начальные значения, одинаковые границы, пустое поле, обратный диапазон, сброс результата, блокировка полей, защита от двойной отправки и восстановление формы после ошибки связи.

## Адаптивность и доступность (этап 5)

На широком экране поля расположены в две колонки; при ширине до 600 px — в одну. При ширине до 360 px дополнительно уменьшены отступы и заголовок. Поля и кнопка имеют высоту не менее 48 px. Добавлены видимый клавиатурный фокус, подписи полей, связь полей с сообщением об ошибке и постоянные области объявления результата и ошибки.

В Chrome проверены:

- Ширины 320, 375, 768 и 1280 px, альбомный формат 812 × 375: горизонтального скролла нет.
- Область 640 × 450 CSS-пикселей как проверка переразмещения, эквивалентная доступному пространству окна 1280 × 900 при масштабе 200%. Само переключение масштаба через меню браузера отдельно не проверялось.
- Значение −1000000000 целиком помещается в поля и результат; длинная ошибка, включая непрерывную строку из 120 символов, переносится.
- Порядок Tab: минимум → максимум → кнопка; индикатор фокуса виден.
- В дереве доступности присутствуют имена полей, `alert` и область `aria-live="polite"`. Прослушивание с реальным экранным диктором отдельно не выполнялось.
- Визуально просмотрены снимки с результатом на ширинах 320 и 1280 px; сборка проходит.
