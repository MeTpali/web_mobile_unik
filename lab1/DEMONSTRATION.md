# Полная демонстрация лабораторной №1

Вариант №6 — генератор случайных чисел. Браузерный проект и Flutter-проект вместе составляют одну лабораторную. Все команды ниже — для Bash на Ubuntu, а не PowerShell из старых README.

## 1. Подготовить окружение и сеть

Открыть терминал на ПК:

```bash
cd ~/Unik/web_mobile_unik
node --version
npm --version
python3 --version
flutter-aurora --version
flutter-aurora devices
ip -4 addr
ssh -o ConnectTimeout=8 defaultuser@192.168.2.16 'echo SSH_OK'
```

Ожидается Node.js 24 версии не ниже 24.13.0 и ниже 25, доступный Python и установленный Flutter для Авроры. Телефон должен присутствовать в `devices`; SSH должен вывести `SSH_OK`. При проблеме с Flutter выполнить `flutter-aurora doctor -v`. Рабочий PSDK должен содержать target `AuroraOS-5.2.1.200-base-armv7hl`; сам факт наличия chroot недостаточен.

Выбрать IPv4 ПК, доступный телефону. В последней проверке — `192.168.0.104`. Далее в примерах используется этот адрес: если он изменился, заменить его в URL. Не брать адрес Docker, VPN или `127.0.0.1`. USB/SSH-подключение и доступ телефона к API по локальной сети проверяются отдельно.

Проверить, что порты 3000 и 8000 свободны или заняты именно нашими серверами:

```bash
ss -ltnp 'sport = :3000 or sport = :8000'
```

Не завершать неизвестные процессы. Уже работающий нужный сервер можно использовать повторно.

## 2. Подготовить зависимости

Если зависимости уже установлены и исходники не менялись, этот шаг можно пропустить.

```bash
cd ~/Unik/web_mobile_unik/lab1/lab-01
npm ci
cd ~/Unik/web_mobile_unik/lab1/lab-02/backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd ~/Unik/web_mobile_unik/lab1/lab-02/calculator
flutter-aurora pub get
```

При отсутствии `venv` установить `python3-venv` через apt. Если `npm ci` сообщает о несовместимом Node.js, сначала выбрать подходящую версию Node.js, а затем повторить установку.

## 3. Запустить сервер браузерного интерфейса

Терминал A:

```bash
cd ~/Unik/web_mobile_unik/lab1/lab-01
npm run build
npm start
```

Оставить терминал открытым. Express слушает порт 3000 и раздаёт одновременно API и собранную страницу из `dist`. Vite на 5173 для этого показа не нужен. После изменения интерфейса `npm run build` выполнить заново.

Терминал B:

```bash
curl -i http://127.0.0.1:3000/api/health
curl -i http://127.0.0.1:3000/api/random \
  -H 'Content-Type: application/json' \
  -d '{"min":1,"max":100}'
curl -i http://127.0.0.1:3000/api/random \
  -H 'Content-Type: application/json' \
  -d '{"min":10,"max":1}'
```

Ожидается: health — HTTP 200 и `{"status":"ok"}`; правильный диапазон — HTTP 200, JSON с `value` от 1 до 100; обратный диапазон — HTTP 400 с описанием ошибки.

## 4. Показать браузерный интерфейс

На ПК открыть `http://127.0.0.1:3000/`, на телефоне — `http://192.168.0.104:3000/`.

| Действие | Ожидаемый результат |
|---|---|
| Ввести 1 и 100, нажать «Сгенерировать» | Целое число внутри диапазона |
| Повторить кнопкой и клавишей Enter на ПК | Новые запросы без перезагрузки страницы |
| Ввести 42 и 42 | Всегда 42 |
| Ввести −10 и −1 | Отрицательное число в диапазоне |
| Ввести 10 и 1, очистить поле, попробовать дробь | Сообщение о неверном вводе |
| Сузить окно ПК, повернуть телефон | Форма остаётся доступной, поля перестраиваются |

На ПК открыть инструменты разработчика → Network, сгенерировать число и показать `POST /api/random`, JSON запроса и JSON ответа. Объяснить: `async/await` позволяет дождаться ответа, не перезагружая страницу; число вычисляет сервер. Повтор одинакового числа допустим и не является ошибкой.

Для демонстрации ошибки сети остановить сервер в терминале A через Ctrl+C, попробовать генерацию на уже открытой странице. Должна появиться ошибка связи, форма должна снова стать доступной. Запустить `npm start` и повторить успешную генерацию.

Важно: ранее на браузере Авроры была белая страница при работающем `/api/health`. Успех health не доказывает работу интерфейса. Перед защитой отдельно выполнить всю таблицу на телефоне. Если белая страница сохранилась, проверить загрузку JS/CSS, кэш и совместимость движка браузера; записать проблему как незакрытую. Мобильный режим браузера ПК не заменяет показ на реальном телефоне.

## 6. Запустить и показать Flutter-приложение

Из вывода первой команды взять идентификатор физического телефона и подставить вместо `<ID>`:

```bash
cd ~/Unik/web_mobile_unik/lab1/lab-02/calculator
flutter-aurora devices
flutter-aurora run -d <ID> --dart-define=WS_URL=ws://192.168.0.104:8000/ws/random
```

Дождаться запуска. На телефоне проверить адрес `ws://192.168.0.104:8000/ws/random` и нажать «Подключиться».

1. Показать успешное подключение.
2. Сгенерировать несколько чисел для 1…100; показать результат и историю.
3. Проверить 42…42 и −10…−1.
4. Ввести обратный диапазон и пустое поле: показать понятную ошибку.
5. Исправить ввод и снова получить число.
6. Остановить Python-сервер через Ctrl+C. Попробовать генерацию: показать состояние ошибки/разрыва, отсутствие бесконечного ожидания.
7. Снова запустить `.venv/bin/python run.py`, нажать «Подключиться» и повторить генерацию.

Запросы автоматически не переотправляются после разрыва. История содержит последние 10 результатов текущего сеанса и хранится в памяти; её исчезновение после полного закрытия приложения ожидаемо.

Показать формат обмена в исходниках:

```json
{"type":"generate","request_id":"demo-1","min":1,"max":100}
```

```json
{"type":"result","request_id":"demo-1","min":1,"max":100,"value":42}
```

`request_id` связывает ответ с запросом; значение 42 здесь пример. В отличие от браузерной формы, обмен идёт текстовыми JSON-сообщениями внутри постоянного WebSocket-соединения.

## 8. Если что-то не работает

| Симптом | Проверка и действие |
|---|---|
| `EADDRINUSE` | `ss -ltnp 'sport = :3000 or sport = :8000'`; найти уже запущенный сервер |
| На 3000 API есть, страницы нет | Выполнить `npm run build`, проверить каталог `dist` |
| ПК работает, телефон нет | Проверить текущий IP, доступность сети и порт; сначала открыть health на телефоне |
| WebSocket не подключается | Нужны `ws://`, порт 8000 и путь `/ws/random`; `http://` и адрес телефона не подходят |
| `No psdk target found` | Проверить `flutter-aurora config --list` и список target в настроенном PSDK |
| Телефон пропал из SSH/devices | Восстановить USB-подключение в режиме разработчика |

При необходимости посмотреть `sudo ufw status`. Если UFW активен и блокирует доступ, разрешить только нужные порты из фактической локальной подсети; не отключать весь firewall ради показа.

## 9. Завершить демонстрацию

Остановить запущенные вручную серверы через Ctrl+C и завершить Flutter-сеанс из его терминала. Не удалять окружения и проект.

Проверить, что показаны: браузер на ПК и Авроре, адаптивная форма, HTTP-запрос, Flutter на телефоне, WebSocket, ошибки ввода и восстановление после разрыва. Факт работы браузера Авроры фиксировать отдельно от работы нативного приложения.
