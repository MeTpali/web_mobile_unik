# Полная демонстрация ЛР1 · вариант 1 · Калькулятор

Одна лабораторная с браузерным и Flutter-интерфейсами. WebSocket-сервер и Flutter впоследствии проверены после разрешения пользователя. Нативный сценарий прошёл; точные результаты и ограничения — в docs/VALIDATION.md. Далее приведён порядок полного ручного показа.

## 1. Проверить окружение и сеть

```bash
cd ~/Unik/web_mobile_unik/kirik
node --version
npm --version
python3 --version
ip -4 addr
ssh -o ConnectTimeout=8 defaultuser@192.168.2.16 'echo SSH_OK'
ss -ltnp 'sport = :3100 or sport = :8100'
```

Node.js нужен 24.13+ из ветки 24. Адрес ПК в последних проверках — 192.168.0.104, SSH телефона — 192.168.2.16. При смене IP заменить его в URL. Телефон должен иметь маршрут к ПК; localhost на телефоне обозначает сам телефон. Не использовать адрес Docker или VPN. Занятый порт сначала проверить: не запускать два одинаковых сервера и не завершать неизвестные процессы.

## 2. Запустить браузерный калькулятор

Терминал A:

```bash
cd ~/Unik/web_mobile_unik/kirik/lab1/lab-01
npm ci
npm test
npm start
```

Зависимости достаточно установить один раз. Сборка Vite не нужна. Express раздаёт HTML, CSS и ES5 JavaScript из public, порт 3100. Асинхронный XMLHttpRequest позволяет старому браузеру отправлять JSON без перезагрузки страницы.

Терминал B:

```bash
curl -i http://127.0.0.1:3100/api/health
curl -i http://127.0.0.1:3100/api/calculate \
  -H 'Content-Type: application/json' -d '{"a":12.5,"b":2,"operation":"/"}'
curl -i http://127.0.0.1:3100/api/calculate \
  -H 'Content-Type: application/json' -d '{"a":1,"b":0,"operation":"/"}'
```

Ожидается health 200, результат 6.25 с HTTP 200, деление на ноль — HTTP 400 с сообщением. Сервер самостоятельно проверяет типы и операцию, даже если обходят форму.

## 3. Показать интерфейс на ПК и телефоне

На ПК открыть http://127.0.0.1:3100/, на Авроре — http://192.168.0.104:3100/.

| Действие | Ожидается |
|---|---|
| 12.5 + 2 | 14.5 |
| −5 − 2 | −7 |
| −3 * 4 | −12 |
| 7 / 2 | 3.5 |
| 1 / 0 | Сообщение об ошибке, форма не зависает |
| Пустое поле, текст, слишком большое число | Ошибка ввода |
| Число с запятой | В форме преобразуется к числу с точкой |
| Enter на ПК | Вычисление без перезагрузки страницы |
| Узкое окно, поворот телефона | Адаптивная компоновка, элементы доступны |

В Network браузера ПК показать POST /api/calculate, JSON запроса и ответа. Повторить таблицу на реальном телефоне: эмуляция узкого экрана не является проверкой браузера Авроры. Пользователь подтвердил работу формы в браузере Авроры, деление 7/2 и ошибку деления на ноль.

Остановить сервер в A через Ctrl+C, нажать «Вычислить» на уже открытой странице: появляется ошибка связи. Снова запустить npm start и получить результат. Ошибка сети отличается от HTTP 400. Числа double могут иметь обычную погрешность десятичного представления; это не финансовая арифметика.

## 4. Подготовить WebSocket-сервер отдельно

Следующие действия пользователь выполняет после установки нужных зависимостей:

```bash

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Оставить сервер открытым. Во втором терминале:

```bash
cd ~/Unik/web_mobile_unik/kirik/lab1/lab-02/backend
curl http://127.0.0.1:8100/health
.venv/bin/python smoke_client.py --url ws://127.0.0.1:8100/ws/calculate
.venv/bin/python -m pytest -q
```

Планируемый итог smoke-клиента — PASS WebSocket calculator: обычные вычисления, ошибка деления на ноль и успешный запрос после неё в том же соединении. Серверные тесты (11 passed) и реальный smoke-обмен выполнены.

## 5. Подготовить Flutter и показать вычисления

В установленном Flutter для Авроры:

```bash
cd ~/Unik/web_mobile_unik/kirik/lab1/lab-02/calculator
flutter-aurora pub get
flutter-aurora devices
flutter-aurora run -d <ID> --dart-define=WS_URL=ws://192.168.0.104:8100/ws/calculate
```

<ID> заменить идентификатором физического телефона из devices. Если оболочки flutter-aurora нет в PATH, использовать ~/.local/opt/flutter_aurora_linux/bin/flutter. Ошибка пустого списка PSDK targets означает необходимость проверить настроенный armv7hl target, а не править прикладной код.

1. На телефоне проверить ws://192.168.0.104:8100/ws/calculate и нажать «Подключиться».
2. Выполнить все четыре операции из таблицы; показать историю.
3. Разделить на ноль, затем выполнить правильное вычисление без закрытия сокета.
4. Показать ошибку пустого поля и отрицательные/дробные значения.
5. Остановить Python-сервер, попробовать вычисление: показать разрыв или тайм-аут.
6. Запустить сервер снова, переподключиться и получить результат.

Запросы автоматически не повторяются. История хранит последние 10 вычислений текущего сеанса, после закрытия очищается. Пример протокола:

```json
{"type":"calculate","request_id":"demo-1","a":7,"b":2,"operation":"/"}
```

```json
{"type":"result","request_id":"demo-1","a":7,"b":2,"operation":"/","value":3.5}
```

request_id связывает ответ с конкретным запросом. Ошибка передаётся JSON-сообщением type:error, а не HTTP-статусом после установления сокета. Для будущей проверки Flutter предусмотрены flutter-aurora analyze и тест контроллера; при проблемах тестового runner Авроры использовать обычный совместимый Flutter SDK. Статический анализ и отдельный нативный сценарий прошли; локальный flutter test не запустился из-за отсутствующего Linux patched SDK.

## 6. Показать код и завершить

Открыть server/calculator.js и server/app.js браузерного проекта: вычисления отделены от HTTP. public/app.js содержит UI, public/api.js — асинхронный сетевой сервис, styles.css — @media. В Python calculator.py отделён от protocol.py и main.py. Во Flutter lib/models, controllers, services и ui отвечают за разные уровни. Подробный разбор — EXPLANATION.md.

При ошибке подключения проверить правильный порт и путь: браузер 3100, WebSocket 8100/ws/calculate. Если API с телефона работает, а страница белая, проверить загрузку JS/CSS и кэш; health не доказывает работоспособность UI. Если UFW активен, проверить правила доступа нужных портов из фактической локальной сети, не отключая весь firewall.

В конце остановить собственные серверы через Ctrl+C. Снимки экрана телефона не делать — политика запрещает; демонстрировать непосредственно на устройстве. Завершённая сдача требует обеих интерфейсных демонстраций, выполненные проверки записаны в docs/VALIDATION.md.
