Задания по курсу Разработка мобильных и web-приложений

**Лабораторная работа №1. Взаимодействие с web-клиентом и WebSockets в мобильном приложении Aurora OS.**

**Часть 1.** Необходимо разработать серверное программное обеспечение на любом языке программирования, реализующее логику работы в соответствии с вариантом. Данное серверное обеспечение должно взаимодействовать с пользователем посредством браузера, иметь web-интерфейс. Для реализации web-интерфейса необходимо создать файлы html, css и js. Файлы js должны обеспечивать функции управления пользовательскими действиями, обрабатывать нажатия на кнопки web-формы. Кроме того, необходимо добавить асинхронный вызов js (async, promise и т.д.). В css файле обеспечить адаптивную верстку под различные разрешения экрана с использованием @media.

Реализованное программное обеспечение запускается в локальной сети. Демонстрируется работа приложения в браузере десктопной ОС (ПК) и в браузере мобильного телефона под управлением ОС Аврора.

**Часть 2.** Необходимо разработать приложения на Qt (возможны варианты с flutter) для запуска на мобильном устройстве под управлением ОС Аврора. Данное приложение должно взаимодействовать с сервером посредством передачи данных через сокеты (web-сокеты). Запустить сервер на удаленном устройстве (ПК), обеспечить подключение мобильного устройства к серверу в локальной сети и взаимодействие приложения с сервером.

Варианты заданий:

Вариант №1: Простой калькулятор. Пользователи вводят два числа и выбирают операцию (+, -, \*, /). Результат вычисляется и выводится на экран.

Вариант №2: Бесконечный таймер обратного отсчета. Таймер ведет обратный отсчет с указанного пользователем начального значения (например, секунд). По завершении таймера появляется сообщение о завершении.

Вариант №3: Контактная форма обратной связи. Форма для отправки письма администратору ресурса с поля ввода имени, адреса email и сообщения. После заполнения формы данные отправляются на сервер и возвращаются обратно подтверждение отправки.

Вариант №4: Минималистичный чат. Очень простой интерфейс чата, позволяющий отправлять короткие сообщения другим пользователям. Сообщения передаются на сервер и отображаются мгновенно всем участникам.

Вариант №5: Преобразователь температуры. Конвертер градусов Цельсия в Фаренгейты и наоборот. Пользователь вводит температуру, выбирает единицу измерения исходной величины, нажимает кнопку преобразования, и получает результат.

Вариант №6: Генератор случайных чисел. Программа генерирует случайное число в указанном диапазоне. Диапазон задаётся пользователем, после чего кнопка вызывает генерацию случайного числа и выводит его на экран.

Вариант №7: Сервер статистики аналитики сайта. Простое решение для сбора статистической информации о посетителях сайта: количество просмотров страниц, уникальные посетители, длительность сессий. Данные собираются асинхронно через JS и сохраняются на сервере с визуализацией результатов в виде графиков или диаграмм.

**Лабораторная работа №2. REST API, HTTPS и offline-клиент на Aurora OS.**

**Часть 1.** Серверная часть на ПК. Реализовать REST API с версионированием, например через /api/v1/. Поддержать CRUD-операции GET, POST, PUT или PATCH и DELETE. Использовать JSON как формат обмена. Возвращать корректные коды состояний 200, 201, 204, 400, 401, 403, 404 и 500. Настроить заголовки Content-Type, Accept, Host и User-Agent. Реализовать аутентификацию через JWT или cookie. Настроить HTTPS с самоподписанным сертификатом. Добавить кэширование через ETag, Cache-Control и Last-Modified. Задокументировать API через OpenAPI или Swagger.

**Часть 2**. Вспомогательная браузерная часть на мобильном устройстве. Открыть Swagger UI или тестовую HTML-страницу в браузере на ПК. Выполнить через неё основные запросы к API: создание, чтение, обновление и удаление. Подключить телефон Аврора к той же сети. Открыть ту же страницу в браузере на Аврора. Убедиться, что запросы к API работают с мобильного браузера.

**Часть 3.** Основная нативная часть на мобильном устройстве. Разработать нативное приложение на Qt, QML и C++ для ОС Аврора. Реализовать асинхронные HTTP-запросы через QNetworkAccessManager. Реализовать парсинг JSON через QJsonDocument, QJsonObject и QJsonArray. Реализовать хранение токена или cookie между сессиями через QSettings и QNetworkCookieJar. Реализовать локальный кэш на SQLite через QtSql для offline-режима. Реализовать CRUD-операции через REST API. Обрабатывать ошибки сети, таймауты, коды 4xx и 5xx. Продемонстрировать на телефоне полный CRUD-цикл, работу offline с показом кэшированных данных, восстановление сети и синхронизацию, а также обработку ошибок.

Варианты заданий:

Вариант №1: Список задач. Сервер хранит задачи с полями заголовок, описание, статус, срок. Приложение позволяет создавать, просматривать, редактировать и удалять задачи, работать offline и синхронизироваться.

Вариант №2: Заметки. Сервер хранит заметки с полями заголовок, текст, теги, дата создания. Приложение позволяет создавать, просматривать, редактировать и удалять заметки, работать offline и синхронизироваться.

Вариант №3: Контакты. Сервер хранит контакты с полями имя, телефон, email, организация. Приложение позволяет создавать, просматривать, редактировать и удалять контакты, работать offline и синхронизироваться.

Вариант №4: Рецепты. Сервер хранит рецепты с полями название, ингредиенты, шаги приготовления, время. Приложение позволяет создавать, просматривать, редактировать и удалять рецепты, работать offline и синхронизироваться.

Вариант №5: Тренировки. Сервер хранит тренировки с полями дата, тип, длительность, количество подходов. Приложение позволяет создавать, просматривать, редактировать и удалять записи о тренировках, работать offline и синхронизироваться.

Вариант №6: Расходы. Сервер хранит расходы с полями дата, категория, сумма, комментарий. Приложение позволяет создавать, просматривать, редактировать и удалять расходы, работать offline и синхронизироваться.

Вариант №7: Инвентарь. Сервер хранит предметы инвентаря с полями название, количество, место хранения, состояние. Приложение позволяет создавать, просматривать, редактировать и удалять записи, работать offline и синхронизироваться.

Вариант №8: Книги. Сервер хранит книги с полями автор, название, год, жанр, статус чтения. Приложение позволяет создавать, просматривать, редактировать и удалять книги, работать offline и синхронизироваться.

Вариант №9: Музыкальная коллекция. Сервер хранит альбомы с полями исполнитель, альбом, год, жанр. Приложение позволяет создавать, просматривать, редактировать и удалять записи, работать offline и синхронизироваться.

**Лабораторная работа №3. Сборка, подпись, деплой и масштабирование приложений Aurora OS.**

**Часть 1.** Серверная инфраструктура на ПК или в облаке. Развернуть серверную часть из второй лабораторной или новую. Настроить автозапуск через systemd. Настроить nginx как reverse proxy. Запустить два или три экземпляра приложения через Docker или systemd-шаблоны. Реализовать балансировку нагрузки. Выполнить blue-green или канареечный деплой новой версии. Проверить отказоустойчивость, отключая один экземпляр и убеждаясь, что сервис продолжает работать.

**Часть 2.** Основная нативная часть на мобильном устройстве. Собрать RPM-пакет для Aurora OS с помощью rpmbuild. Подписать пакет сертификатом разработчика через sign_package. Установить подписанный RPM на реальный телефон. Настроить приложение на работу через балансировщик. Реализовать WebSockets для push-уведомлений. Реализовать проверку доступности серверов и повторные попытки. Проверить отказоустойчивость: отключить один backend и показать, что приложение продолжает работать. Продемонстрировать обновление версии без простоя через blue-green. Показать получение push-уведомления.

Варианты заданий как в 1-ой или 2-ой лабораторной работе.
