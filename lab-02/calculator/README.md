# Flutter — генератор случайных чисел

Лабораторная № 2, вариант 6. Проект сохраняет имя пакета `calculator` и существующую платформу `aurora`, но реализует генератор чисел.

Экран содержит адрес сервера, подключение/отключение, целочисленный диапазон, результат и последние 10 результатов текущего сеанса. Обе границы включены; допустимы значения от −1 000 000 000 до 1 000 000 000. Вычисление выполняет Python, клиент отправляет текстовый JSON через постоянный WebSocket `/ws/random`, сопоставляет ответы по `request_id` и показывает ошибки сервера.

## Запуск

На ПК из `lab-02/backend`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

С Flutter SDK для Авроры из `lab-02/calculator`:

```bash
flutter pub get
flutter devices
flutter run -d <идентификатор-устройства>
```

На экране укажите `ws://<IP-ПК>:8000/ws/random` и нажмите «Подключиться», затем задайте диапазон и нажмите «Сгенерировать». ПК и телефон должны быть в одной локальной сети, порт 8000 должен быть доступен с телефона. `localhost` на телефоне обозначает сам телефон.

Начальный адрес можно задать при запуске:

```bash
flutter run -d <идентификатор-устройства> --dart-define=WS_URL=ws://192.168.1.10:8000/ws/random
```

После потери связи нажмите «Подключиться». Подключение и ответ ограничены 10 секундами; запросы автоматически не повторяются. При выходе соединение закрывается. История хранится только в памяти. Клиент использует `dart:io` и предназначен для нативного приложения; Flutter Web не поддерживается.

## Проверки

```bash
flutter analyze
flutter test
```

Тесты проверяют мобильную компоновку и реальный локальный WebSocket: результат, серверную ошибку, следующий успешный запрос и переподключение. Для сдачи также необходимо продемонстрировать работу с Python-сервером на физическом устройстве под ОС Аврора; автоматические тесты эту проверку не заменяют.

## Структура клиента

- `main.dart` — запуск; `app.dart` — тема и создание зависимостей.
- `ui/` — экран и отдельные карточки подключения, диапазона, результата и истории.
- `controllers/generator_controller.dart` — состояние, действия, корреляция запросов, тайм-аут ответа и история.
- `models/` — диапазон с правилами валидации и результат генерации.
- `services/random_service.dart` — интерфейс сервиса, WebSocket-транспорт и JSON-протокол. Не зависит от Flutter.

Контроллер получает `RandomService` через конструктор. UI получает фабрику контроллера из `app.dart` и не создаёт сетевой сервис. Состояние доступно через геттеры; история доступна только для чтения. Логика контроллера проверяется с подставным сервисом отдельно от теста настоящего WebSocket.

## Flutter для Авроры 3.41.4

Платформенные `main.cpp`, `CMakeLists.txt` и RPM spec обновлены по шаблону Flutter для Авроры 3.41.4. Макросы `defines.inc` и `requires.inc` создаёт Flutter при сборке; вручную их создавать не нужно. Разрешение Internet указано в `pubspec.yaml` и desktop-файле.

Ошибка `No psdk target found for platform arm` при пустом списке означает, что настроенный PSDK не содержит доступных таргетов. Для TrustPhone, определённого как `arm`, требуется `armv7hl`. Установите Chroot, Tooling и Target armv7hl версии 5.2.1.200; один Chroot недостаточен.

Проверьте конфигурацию и список таргетов:

```bash
flutter-aurora config --list
~/AuroraPlatformSDK/sdks/aurora_psdk/sdk-chroot sdk-assistant list
flutter-aurora doctor -v
```

Если PSDK установлен в другом каталоге, исправьте путь через `flutter-aurora config --aurora-psdk-dir /путь/к/sdks/aurora_psdk`.
