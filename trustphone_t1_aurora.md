# TrustPhone T1 с ОС Аврора: общая инструкция для разработки

Актуализировано **4 ноября 2026 года**.

Документ описывает доступный экземпляр телефона и установленную среду разработки.
Его задача — дать исходный контекст для любого нового проекта и сократить повторную
диагностику. Здесь нет архитектуры отдельных приложений, их настроек, учётных
данных, установленных версий или результатов проектных испытаний.

Характеристики относятся к этому устройству и текущей версии ОС. После обновления
ОС или SDK повторно сверять изменившиеся параметры, а не всё окружение целиком.

## 1. Основные правила

- Подключение к телефону: `ssh defaultuser@192.168.2.16`. Доступ по существующему
  ключу подтверждён 04.11.2026. Адрес может измениться при другом подключении.
- Ядро — aarch64, пользовательская система — **32-битная ARM hard-float**.
  Использовать RPM **armv7hl** и Flutter target **aurora-arm**.
- Для Flutter использовать установленный **Flutter Aurora**, а не обычный Flutter.
- Зависимости Flutter получает пользователь с необходимым российским VPN.
  Ассистент не запускает `pub get` самостоятельно; анализ и сборка — с `--no-pub`.
- `/home` имеет `noexec`: `chmod +x` не разрешает запуск скопированного ELF.
  Устанавливать приложения через RPM; не менять флаги монтирования.
- GUI запускать штатно через launcher/invoker с разрешениями приложения.
  Не обходить песочницу ради устранения ошибки доступа.
- Скриншоты запрещены политикой телефона и указанием владельца. Использовать
  журналы и текстовую проверку; не пытаться обходить запрет.
- Сначала читать журнал и проверять конкретную причину. Не переустанавливать SDK,
  не пересобирать всё и не повторять полные тесты без нового основания.

## 3. SSH и доступные команды

На компьютере:

```bash
ssh -o BatchMode=yes -o ConnectTimeout=8 \
  -o ServerAliveInterval=5 -o ServerAliveCountMax=1 \
  defaultuser@192.168.2.16
```

При `Connection refused` проверить на телефоне режим разработчика, разрешение
удалённого подключения и выбранный USB-режим. При тайм-ауте проверить подключение
и адрес. Не менять сетевые настройки наугад. В ограниченной среде ассистента
`socket: Operation not permitted` может означать запрет сети на компьютере:
требуется разрешённый запуск команды, а не настройка телефона.

Подтверждены `/bin/bash`, BusyBox, `netstat`, `busctl`, `invoker`, `sdk-deploy-rpm`,
`file`, `journalctl`, `rpm`, `findmnt`, `getconf`, `curl`.
В проверенном SSH PATH отсутствуют `python3`, `ss`, `ip`, `readelf`, `rg`;
`busybox ifconfig` недоступен. Искать по файлам предпочтительно на компьютере;
на телефоне использовать доступные средства, например `grep`.

Минимальная диагностика при соответствующем симптоме:

```sh
cat /etc/os-release
uname -srmo
getconf LONG_BIT
getconf GNU_LIBC_VERSION
findmnt -no TARGET,FSTYPE,OPTIONS /home
findmnt -T /opt/app -no TARGET,FSTYPE,OPTIONS
netstat -lnt
ps -eo pid,comm,args
```

Не выполнять весь список перед каждой задачей. Занятые порты, PID, свободное место
и состояние процессов меняются; не считать старый вывод текущим состоянием.
Перед завершением процесса сверять свежий PID и команду. Не применять широкие
`killall` и не удалять данные приложения для недиагностированной ошибки.

В неинтерактивной SSH-сессии могут отсутствовать `XDG_DATA_HOME`, `LANG`,
`XDG_SESSION_TYPE`. Окружение GUI в песочнице отличается от SSH.

### Flutter

Из корня приложения с уже полученными зависимостями:

```bash
/home/topg/.local/opt/flutter_aurora_linux/bin/flutter analyze --no-pub
/home/topg/.local/opt/flutter_aurora_linux/bin/flutter build aurora \
  --no-pub --debug --target-platform=aurora-arm \
  --psdk-dir=/home/topg/AuroraPlatformSDK/sdks/aurora_psdk
```

Результат находится в `build/aurora/psdk_5.2.1/aurora-arm/debug/RPMS/`.
Aurora использует `aurora_pubspec.lock`; отсутствие обычного `pubspec.lock`
само по себе не означает отсутствие зависимостей.

Не копировать `build` и generated/ephemeral-каталоги между проектами.
`PathExistsException` для `.aurora_plugin_symlinks/aurora_embedder` наблюдалась
из-за скопированного generated-каталога. Сначала проверить его происхождение,
сохранить резервную копию и дать Flutter регенерировать файлы. Не удалять весь
SDK и не менять исходники плагина без необходимости.

Если после обновления Flutter отсутствует `%include %{_sourcedir}/defines.inc`
в RPM spec, проверить миграцию шаблона под установленную версию Flutter Aurora.
Это отдельная проблема от отсутствующего PSDK target.

В этой поставке обычный `flutter test` может не запуститься из-за отсутствующего
Linux tester/patched SDK (`platform_strong.dill`). Не объявлять такие тесты
пройденными. Анализ, сборка, нативная проверка и интерактивный UI-тест — разные
виды проверки; выбирать нужный для изменения.

### Qt/QML

Доступная среда — Qt 5.6, C++11 и Sailfish.Silica 1.0. Не предполагать наличие
API современных Qt. Из каталога приложения с подготовленными build-зависимостями:

```bash
/home/topg/AuroraPlatformSDK/sdks/aurora_psdk/sdk-chroot \
  mb2 -t AuroraOS-5.2.1.200-base-armv7hl --no-pull-build-requires build
```

`--no-pull-build-requires` не устанавливает недостающие зависимости.
Для светлого интерфейса использовать `palette.colorScheme: Theme.DarkOnLight`,
светлый фон страницы и контрастный акцент. Обращаться к локальной `palette`,
проверять также меню, редакторы и обложку, а не только главный экран.

## 5. Подпись и установка RPM

RPM должен соответствовать ABI устройства и требованиям подписи. Для подписи
в SDK доступен `rpmsign-external`, для проверки — его команда `verify`.
Использовать настроенную пару разработчика; не печатать ключи и не переносить
закрытый ключ на телефон. После пересборки подпись нового RPM проверяется заново.
Замечания rpmlint и успешная установка не означают прохождение магазинной валидации.

Общий пример с условным именем пакета, выполняется на компьютере:

```bash
scp ./application.armv7hl.rpm defaultuser@192.168.2.16:/home/defaultuser/
ssh defaultuser@192.168.2.16 \
  'sdk-deploy-rpm --silent --keepUserData /home/defaultuser/application.armv7hl.rpm'
```

`--keepUserData` сохраняет пользовательские данные, включая старые настройки.
`--silent` работает при разрешённой бесшумной установке на устройстве.
Прямой `devel-su rpm -Uvh` для прикладного пакета может отклоняться политикой
с сообщением `is not a system package`; использовать штатный механизм установки,
не отключать проверку пакетов.

Приложения устанавливаются в `/opt/app/<id>/<версия>/`, а `current` указывает
на выбранную версию. Для GUI может быть создана ссылка `/usr/bin/<id>`.
Не зашивать версионный каталог в команды. Один ответ `rpm -q` «не установлен»
недостаточен: проверять `/opt/app/<id>/current` и ссылку запуска.

## 6. Запуск GUI, разрешения и данные

Общий шаблон запуска на телефоне, где `<id>` заменяется идентификатором приложения:

```sh
invoker --single-instance --type=generic /usr/bin/<id>
```

При необходимости независимого запуска по SSH использовать `setsid` и перенаправление
в отдельный журнал. Дождаться завершения старого процесса перед новым запуском.
Готовность определять по журналу или нужному сервису, а не короткой фиксированной паузе.

Для сети приложение должно иметь соответствующее разрешение `Internet` в desktop-
описании. Это относится и к локальному сетевому обмену. Не обходить Firejail.
OrganizationName/ApplicationName влияют на настройки и данные Qt; смена
идентификаторов не переносит данные автоматически.

Путь сохранения определяется API приложения и окружением его процесса.
Не считать каталог, вычисленный из SSH-окружения, доказанным путём внутри GUI.
Файл примера на компьютере не является автоматически конфигурацией телефона.
Не выводить целиком настройки с токенами, паролями и другими секретами.

## 7. Сеть, TLS и WebSocket

- `127.0.0.1` на телефоне — сам телефон. Для сервера на компьютере нужен доступный
  телефону адрес компьютера. При USB и Wi-Fi это могут быть разные адреса.
- Сертификат HTTPS/WSS должен соответствовать адресу подключения. Для IP нужен
  SAN типа IP, для доменного имени — SAN типа DNS; одного CN недостаточно.
- Самоподписанный сертификат требует явного доверия клиента. Передаётся публичный
  сертификат; закрытый ключ остаётся на сервере. Доверие браузера и приложения
  настраивается независимо.
- Для диагностики использовать `curl --cacert <публичный.crt> https://<адрес>/...`.
  `curl -k` не подтверждает исправление доверия или соответствия имени.
- При смене сертификата проверить доверенную копию клиента. При смене адреса
  проверить сохранённые настройки: переустановка с сохранением данных их не сбросит.
- При `Address already in use` сначала найти владельца порта, а не запускать второй
  сервер или завершать произвольные процессы.

Особенности совместимости Qt 5.6, выявленные на этом устройстве:

- В сетевых API могут понадобиться `QIODevice`/`QBuffer` и собственный таймер
  отмены запроса вместо новых перегрузок и `setTransferTimeout`.
- Для WebSocket проверять совместимость сжатия и авторизации обеих сторон.
  Авторизация первым сообщением требует явной поддержки сервера.
- После перезапуска reverse proxy наблюдались проблемы со старым keep-alive.
  При таком симптоме проверить соединение и допустимость повтора; мутации
  нельзя автоматически повторять без защиты от повторного выполнения.
- Наблюдалось зависание при параллельной TLS-инициализации и восстановлении
  сетевых объектов. Проверять порядок создания соединений и изменения глобальной
  SSL-конфигурации. Универсальная причина и полное устранение не установлены;
  не отключать TLS и не повторять зависающий тест бесконечно.

## 8. Системные уведомления

На устройстве проверена публикация через `Nemo.Notifications 1.0`.
Для QML-компонента требуется пакет `nemo-qml-plugin-notifications-qt5`.
Используются `Notification.publish()`, системный `replacesId`, `previewSummary`
и `previewBody`. Повторная публикация с тем же ID обновляет запись.

`Notification` не имеет default property для произвольных дочерних объектов.
Например, подписку внутри него объявлять как свойство:

```qml
property Connections subscription: Connections {
    target: controller
}
```

Видимость баннера зависит от настроек и политики ОС. Постоянный WebSocket сам
по себе не обеспечивает доставку после полного завершения приложения:
фоновые требования необходимо решать отдельно в рамках возможностей ОС.

## 9. Проверки без лишней повторной диагностики

- Использовать уже подтверждённые ABI, Qt и пути SDK как исходный контекст.
  Повторять проверку при обновлении среды или связанном симптоме.
- Проверять изменение на подходящем уровне: анализ/сборка, целевой тест,
  при необходимости запуск на устройстве. Не повторять весь стенд после правки текста.
- Запущенный процесс и созданный Flutter engine не доказывают правильность вёрстки.
  Для визуальных изменений нужна отдельная ручная оценка без скриншотов.
- При `VM Service not yet ready` дождаться строки готовности debug VM Service.
  Его порты и токены динамические. Не сохранять их как постоянные команды.
- `No compilation service available` у VM Service evaluate не обязательно означает
  неисправность приложения. Выбирать поддерживаемый способ диагностики.
- Предупреждение `wl-shell is a deprecated shell extension` встречалось при
  успешном запуске GUI и само по себе не означает ошибку QML.
- Не запускать одновременно проверки, меняющие один конфиг или общие данные.
- Фиксировать, что реально проверено. Сборка, подпись, установка, функциональность,
  визуальная оценка и работа после перезагрузки — отдельные критерии.

При работе с другим устройством или другой версией ОС заново сверить ABI,
совместимость SDK, разрешения и доступные API. Этот документ описывает конкретную
проверенную среду, а не все устройства Авроры.
