# Как устроена вторая лабораторная

## От действия пользователя к серверу

Для примера пользователь вводит «125,50» и нажимает «Сохранить».

1. QML-страница `ExpenseDialog.qml` передаёт строки контроллеру. Она не знает URL API и не выполняет SQL.
2. `ExpenseController::save` проверяет дату, категорию, длину комментария, формат суммы. Сумма превращается в целые `12550` копеек. UUID создаётся на телефоне, поэтому сервер не нужен для создания записи offline.
3. `LocalStore::enqueue` одной SQLite-транзакцией сохраняет расход и операцию в `outbox`. Если приложение закроется после этого, изменение останется на диске.
4. Контроллер уведомляет QML сигналом `changed()`. Благодаря `Q_PROPERTY(... NOTIFY changed)` интерфейс перечитывает расходы и счётчик очереди.
5. Если offline-режим выключен, `sync()` начинает отправку очереди. Повторное нажатие во время работы ничего не запускает: флаг `running` защищает состояние.
6. `ApiClient` отправляет запрос через `QNetworkAccessManager`, подписывается на завершение ответа и запускает таймер. GUI-поток продолжает обрабатывать события.
7. FastAPI проверяет JWT, право записи и схему данных. Сервер в одной транзакции сохраняет расход и квитанцию выполненной операции.
8. Qt получает JSON-ответ. Контроллер передаёт подтверждение в `LocalStore::acknowledge`: версия сервера заменяет локальную, операция удаляется из очереди.
9. После опустошения очереди клиент запрашивает актуальный снимок сервера и сохраняет его в SQLite. При неизменном ETag достаточно ответа 304 без тела.

## C++ и связь с QML

`QObject` участвует в системе сигналов Qt. `Q_OBJECT` включает метаинформацию, которую генерирует moc при сборке. Без неё QML не увидит свойства и вызываемые методы.

`Q_PROPERTY` описывает свойство для QML. Например, чтение `controller.busy` вызывает C++-геттер `busy()`. `NOTIFY changed` указывает сигнал, после которого QML должен пересчитать привязки. `Q_INVOKABLE` делает метод доступным из QML.

`connect(sender, signal, receiver, lambda)` связывает событие с функцией. Лямбда `[this, id](ApiResult r)` сохраняет указатель на контроллер и копию идентификатора для использования после завершения сети. Здесь нельзя захватывать локальные переменные по ссылке, если функция уже завершится к моменту вызова.

`const` у методов хранилища означает, что метод логически читает состояние. `auto` просит компилятор вывести статический тип. Указатели на `QObject` с родителем удаляются при удалении родителя; поэтому буфер, таймер и ответ не требуют ручного `delete` в каждой ветке. `deleteLater()` удаляет ответ после обработки текущего события.

Qt на телефоне — 5.6.3. Поэтому таймаут сделан через QTimer, а тело `sendCustomRequest` передаётся как QBuffer/QIODevice. Современные примеры Qt 6 с другими перегрузками здесь могут не собраться.

## Почему сумма в копейках

Десятичные дроби вроде 0.1 не всегда точно представимы двоичным float. В базе и JSON используется целое число копеек, а на экране оно форматируется в рубли. Контроллер разбирает целую и дробную часть строки отдельно, без умножения пользовательского float на 100. QJsonValue хранит числа как double, но выбранные целые значения до 100 000 000 000 представляются точно.

## Версии и повтор запросов решают разные задачи

`If-Match: "2"` означает: «Измени запись, только если её версия всё ещё 2». Сервер увеличивает версию при каждом изменении. Если браузер уже изменил эту запись, сервер возвращает 409 с текущей версией. Так приложение не затирает чужую правку молча.

`Idempotency-Key` означает: «Этот конкретный запрос уже мог выполниться». Например, сервер сохранил расход, но ответ потерялся. Повтор POST с тем же ключом и телом возвращает сохранённую квитанцию вместо второго создания. Квитанция хранится в той же транзакции, что и запись. Проверка квитанции выполняется до проверки версии: повтор уже выполненного PATCH должен вернуть успех, даже если версия после него выросла.

Ключ нельзя повторять с новым телом. Поэтому очередь фиксирует `attempted` до первого сетевого обращения и не позволяет изменять такую операцию до получения квитанции. Неотправленные изменения одной записи можно объединять: POST + редактирование остаётся POST, а POST + DELETE отменяет создание целиком.

## Offline — не только отображение старого списка

`items` хранит локальные расходы, `outbox` — намерения пользователя. Изменение обеих таблиц выполняется транзакционно. Для удаления расход скрывается из списка, но операция DELETE остаётся в очереди. На сервере удаление оставляет tombstone с новой версией: другие клиенты узнают, что запись удалена.

Очередь отправляется последовательно. Затем загружается полный серверный снимок с `include_deleted=true`. Заменять кэш снимком при непустой очереди нельзя: это затёрло бы неотправленные изменения.

`scope = URL + логин` разделяет кэши разных серверов и пользователей. QSettings хранит последний адрес, логин, токен, путь к сертификату и offline-переключатель. SQLite-кэш не зашифрован; это учебная реализация локального хранения, а не защищённое хранилище финансовых данных.

## Что означают заголовки

| Заголовок | Назначение в проекте |
|---|---|
| Content-Type | Формат отправленного тела; для запросов с JSON — application/json |
| Accept | Клиент ожидает JSON |
| Host | Имя/адрес сервера из URL; задаётся HTTP-библиотекой |
| User-Agent | Идентификация клиента; нативный клиент задаёт AuroraExpenses/1.0 Qt/5.6 |
| Authorization | JWT после слова Bearer |
| ETag | Валидатор представления; для отдельного расхода — его версия |
| If-None-Match | Условный GET: при совпадении сервер возвращает 304 |
| Last-Modified | Время изменения представления |
| Cache-Control | private, no-cache: приватный кэш с обязательной проверкой актуальности |
| If-Match | Ожидаемая версия при PATCH/DELETE |
| Idempotency-Key | Идентификатор конкретной операции для безопасного повтора |

ETag списка рассчитывается по содержимому. Last-Modified имеет секундную точность, поэтому сервер осторожно сравнивает его с полной датой изменения: несколько правок за секунду не должны ошибочно приводить к 304. При наличии If-None-Match он имеет приоритет над датой.

## TLS и аутентификация

Сертификат подтверждает сервер, JWT — пользователя. Это независимые проверки. Нативный клиент доверяет конкретному публичному сертификату и продолжает проверять SAN/адрес. Код не вызывает `ignoreSslErrors()`.

JWT подписан, но не зашифрован. Он передаётся только по HTTPS. Сервер проверяет подпись, срок действия и наличие пользователя; роль берёт из БД. Пароль хранится как PBKDF2-хеш с отдельной случайной солью. Сохранённый JWT-ключ позволяет серверу переживать перезапуск без принудительного выхода всех клиентов.

## Как читать тесты

`backend/tests/test_api.py` проверяет контракт HTTP и состояния БД без реального телефона. Сбой базы для 500 подставляется только в тесте, отдельной опасной «сломай сервер» ручки нет.

`client/tests/core_tests.cpp` использует настоящие Qt Network и QtSql на телефоне. Сначала проверяет очередь и конфликты локально. Затем через HTTPS создаёт расход offline, пересоздаёт контроллер, синхронизирует, создаёт внешнюю конфликтующую правку, разрешает конфликт, удаляет запись и проверяет 304. Это тест бизнес-логики и транспорта, а не автоматическая проверка всех нажатий QML-интерфейса.
