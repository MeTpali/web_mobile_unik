# Снимки для отчёта по ЛР2 · вариант 6

Номера ниже совпадают с разделом 2.5 в `../reports/Отчёт_ЛР_02.md` и DOCX. Лабораторная оформляется одним отчётом. В задании количество фотографий не установлено; ниже оставлен компактный набор для явно требуемых демонстраций. Реализация async/@media, JSON, HTTP-заголовков, авторизации и кэширования также описана в тексте и листингах отчёта; отдельные фотографии кода не нужны.

## Как снимать и сохранять

1. На ноутбуке используйте штатный инструмент снимков экрана. Экран телефона фотографируйте другим устройством: держите камеру параллельно экрану, уберите блики, дождитесь фокусировки. Проверьте читаемость текста перед переходом к следующему состоянию.
2. Создайте каталог `docs/screenshots/manual/` внутри этой лабораторной. Сохраняйте PNG или JPG с именами из шагов ниже. Если нужны два кадра, добавляйте `-a`, `-b`; например `lr2-03-mobile-crud-a.jpg`. Обычно достаточно одного кадра на рисунок; два кадра нужны только для CRUD на телефоне в ЛР2.
3. В кадре оставляйте нужную форму, результат, статус или терминальную команду. Пароль должен быть скрыт; JWT и секреты сервера не снимайте. Скрин с пустой формой или только запущенным сервером не заменяет результат действия.
4. В DOCX замените строку `[Место для изображения: …]` соответствующим фото через «Вставка → Изображения», сохранив подпись ниже. При нескольких кадрах вставьте их под одной подписью. В Markdown замените строку ссылками вида `![Описание](../lab2/docs/screenshots/manual/ИМЯ.jpg)`.
5. Делайте кадры только после получения описанного результата. Если он отличается, сначала разберитесь с ошибкой. Сырые фотографии храните вместе с проектом. После ручного заполнения отчётов не запускайте генератор без резервной копии: он создаёт отчёты заново с пустыми местами.

## Подготовка

Команды ниже предполагают, что зависимости и приложения уже установлены. Для установки с нуля используйте `README.md` и `DEMONSTRATION.md` этой лабораторной.

Определите текущий адрес ноутбука командой `ip -4 addr`. Далее `IP_ПК` заменяйте реальным адресом, доступным телефону. SSH-адрес телефона `192.168.2.16` не является адресом сервера. Ноутбук и телефон должны иметь сетевой маршрут друг к другу. Если порт занят, проверьте уже работающий сервер, прежде чем запускать второй.

Адрес интерфейса и API: `https://IP_ПК:8443`. Учебный вход: `demo` / `demo12345`. Клиент: **«Расходы ЛР2»**. Встроенный сертификат: `/usr/share/com.example.expenseslab2/certificates/server.crt`.

Сертификат на сервере и сертификат в установленном RPM должны соответствовать друг другу; IP должен входить в SAN. Если адрес изменился, сначала выполните обновление сертификатов по `DEMONSTRATION.md`, а затем начинайте съёмку. Для браузера используйте доверие учебному сертификату. Предупреждение TLS само по себе не является кадром успешной работы HTTPS.

В рабочем терминале:

```bash
cd ~/Unik/web_mobile_unik/lab2
export LAB_URL=https://IP_ПК:8443
```

В отдельном терминале запустите backend и оставьте работающим:

```bash
cd ~/Unik/web_mobile_unik/lab2/backend
.venv/bin/python run.py
```

Образец записи: дата — сегодня, категория «Учёба», сумма 125.50, комментарий «Фото ЛР2». Метки «Фото …» из шагов вводите в комментарий, чтобы отличать записи.

В основном клиенте вход, сертификат и offline находятся на главном экране; к очереди и списку при необходимости прокрутите страницу. Создание — «Новый расход», изменение/удаление — меню записи долгим нажатием.

## Последовательность кадров

### 2.1. Работа с REST API через браузер ПК

Имя: `lr2-01-web-crud.png` (или `.jpg`).

Откройте тестовую HTML-страницу по HTTPS и войдите как demo. Создайте запись по образцу из подготовки, прочитайте её в списке, измените описание/комментарий на «Изменено в браузере», затем удалите. После этого создайте «Фото браузер» и оставьте для следующего шага. Сделайте один снимок страницы с этой записью и HTTPS-адресом. Требование: создание, чтение, обновление и удаление через браузер ПК. Весь цикл выполняется вручную, отдельные фото каждого запроса не нужны.

### 2.2. Доступ к API из браузера Авроры

Имя: `lr2-02-phone-browser.png` (или `.jpg`).

В браузере телефона откройте ту же HTTPS-страницу и войдите как demo. Убедитесь, что «Фото браузер» читается; измените запись и сохраните. Сделайте один кадр страницы с результатом. Требование: запросы к API из мобильного браузера.

### 2.3. Полный CRUD-цикл в нативном приложении

Имя: `lr2-03-mobile-crud.png` (или `.jpg`).

Откройте отдельный клиент ЛР2, задайте HTTPS-адрес и сертификат, выключите offline, войдите как demo. Создайте «Фото мобильная», проверьте её в списке, измените описание/комментарий на «Изменено на телефоне» и сохраните. Снимите обновлённую запись. Удалите её, дождитесь завершения удаления и сделайте второй кадр списка без неё. Требование: полный CRUD на телефоне; достаточно этих двух кадров под одной подписью. Настройки входа отдельно не снимайте.

### 2.4. Кэшированные данные и изменение записи offline

Имя: `lr2-04-offline-cache.png` (или `.jpg`).

Онлайн создайте «Фото offline» и синхронизируйте. Включите «Работать offline», откройте сохранённый список и измените описание/комментарий на «Изменено offline». Снимите один кадр с записью и признаком offline или неотправленного изменения. Требование: offline с кэшированными данными. Перезапуск и полный offline CRUD отдельно снимать не нужно.

### 2.5. Обработка сетевой ошибки в мобильном приложении

Имя: `lr2-05-network-error.png` (или `.jpg`).

Оставьте backend остановленным: в его терминале нажмите Ctrl+C. На телефоне выключите ручной offline и запустите синхронизацию. Дождитесь ошибки связи или тайм-аута, снимите один кадр с сообщением; сохранённые данные должны оставаться доступны. Требование: обработка сетевых ошибок и тайм-аутов. Это реальная недоступность сервера, поэтому не заменяйте её одним переключателем offline.

### 2.6. Восстановление соединения и синхронизация

Имя: `lr2-06-offline-sync.png` (или `.jpg`).

Запустите backend прежней командой. При выключенном offline синхронизируйте телефон; дождитесь отправки правки «Изменено offline» и нулевой очереди. Обновите браузер ноутбука и проверьте ту же правку. Сделайте один кадр браузерного списка с полученной с телефона правкой. Требование: восстановление сети и синхронизация. Отдельные кадры настроек, конфликта и перезапуска не нужны.

## После съёмки

Сверьте имена файлов и номера рисунков с отчётом. Проверьте читаемость каждого кадра в масштабе страницы A4. Удалите через интерфейс только собственные записи «Фото …» и синхронизируйте. Остановите серверы, запущенные вручную, если они больше не нужны. Для ЛР3 оставьте трафик на blue.
