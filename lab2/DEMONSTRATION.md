# Полная демонстрация лабораторной №2

Вариант №6 — расходы. Показываем REST API по HTTPS, браузер на ПК и Авроре, приложение **«Расходы ЛР2»**, локальный кэш, offline CRUD, синхронизацию и конфликты. Клиент ЛР3 для этой работы не использовать.

## 1. Подготовить всё до показа

```bash
cd ~/Unik/web_mobile_unik/lab2
python3 --version
ip -4 addr
ssh -o ConnectTimeout=8 defaultuser@192.168.2.16 'echo SSH_OK'
openssl x509 -in certificates/server.crt -noout -dates -ext subjectAltName
ss -ltnp 'sport = :8443'
```

Примеры используют последний проверенный IP ПК `192.168.0.104`. Если он изменился, заменить адрес в URL. IP должен присутствовать в `subjectAltName` сертификата; текущий сертификат содержит `192.168.0.104` и `192.168.0.118`. SSH-адрес телефона `192.168.2.16` не является адресом API.

Если окружение ещё не подготовлено:

```bash
cd ~/Unik/web_mobile_unik/lab2/backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

В чистой копии без сертификата сначала выполнить из `lab2`:

```bash
bash certificates/generate.sh 192.168.0.104 192.168.0.118
```

Существующий сертификат пересоздавать перед каждым показом не нужно. Если новый IP отсутствует в SAN, сохранить старые файлы в резервном каталоге, выпустить новую пару и пересобрать/переустановить клиент с новым публичным сертификатом. Закрытый ключ остаётся на ПК. Подробности — в [README.md](README.md).

## 2. Запустить сервер и проверить HTTPS

Терминал A:

```bash
cd ~/Unik/web_mobile_unik/lab2/backend
.venv/bin/python run.py
```

Оставить открытым. Если сервер уже работает на 8443 и отвечает health, второй экземпляр не запускать.

Терминал B:

```bash
cd ~/Unik/web_mobile_unik/lab2
curl -i --cacert certificates/server.crt https://192.168.0.104:8443/health
openssl x509 -in certificates/server.crt -noout -fingerprint -sha256
```

Ожидается HTTP 200 и `{"status":"ok"}`. `--cacert` проверяет доверие и имя сервера. `curl -k` для демонстрации TLS не использовать: с ним проверка отключена.

## 3. При необходимости собрать и установить приложение

Оба отдельных клиента уже устанавливались на текущий телефон. Для обычного показа этот шаг пропустить. Для повторной сборки:

```bash
cd ~/Unik/web_mobile_unik/lab2
bash tools/build-client.sh
scp -O client/RPMS/com.example.expenseslab2-1.0.0-3.armv7hl.rpm defaultuser@192.168.2.16:/home/defaultuser/

  'sdk-deploy-rpm --silent --keepUserData /home/defaultuser/com.example.expenseslab2-1.0.0-3.armv7hl.rpm'
```

Сборщик использует настроенный PSDK и armv7hl-target, собирает RPM и проверяет подпись. Если Version/Release менялись, взять имя RPM из вывода сборщика. Ожидаемый итог установки — `Installation successful`. Обычный пакет устанавливать через `sdk-deploy-rpm`, а не `devel-su rpm -Uvh`. Если политика запрещает тихую установку, убрать `--silent` и подтвердить действие на телефоне.

## 4. Показать CRUD в браузере ПК и телефона

На обоих устройствах открыть `https://192.168.0.104:8443/`. Подтвердить доверие к конкретному учебному сертификату, если браузер допускает исключение. При запрете политикой использовать предусмотренный администратором способ доверия; политику не обходить. Для документации API на ПК открыть `/docs` или `/openapi.json`.

Войти как `demo`, пароль `demo12345`. На ПК:

1. Создать расход: дата сегодняшняя в формате `YYYY-MM-DD`, категория `Демо ЛР2 браузер`, сумма по формату поля, комментарий `Создан на ПК`.
2. Обновить список, показать запись и код ответа. В API сумма передаётся целым числом копеек: `12550` = 125,50 ₽.
3. Изменить запись, затем удалить её.
4. Показать JSON, HTTP-код и заголовки в области результата страницы или Network браузера.

Повторить **создание, чтение, редактирование и удаление** в браузере Авроры. Открыть страницу без выполнения CRUD недостаточно. Если Swagger не поддерживается движком телефона, использовать встроенную страницу `/`: внешние CDN ей не нужны.

Ожидаемые коды: создание 201, чтение/изменение 200, удаление 204 без тела. Перед дальнейшими сценариями войти в обоих браузерах именно под `demo`.

4. Долгим нажатием открыть контекстное меню → «Удалить». Дождаться завершения обратного отсчёта удаления и синхронизации.
5. Обновить браузер: запись исчезла.
6. Закрыть приложение полностью и запустить снова. Показать сохранение сессии и кэша; пароль повторно вводить не требуется, пока JWT действителен.

Сворачивание не является закрытием. Для проверки сохранности закрыть приложение средствами интерфейса ОС, затем открыть значок заново.

## 6. Показать offline CRUD и восстановление

Сначала создать онлайн две отдельные записи `Демо offline изменить` и `Демо offline удалить`. Дождаться их появления в браузере и нулевой очереди.

1. Включить «Работать offline» на телефоне. Это управляемый режим демонстрации: приложение сохраняет данные и не отправляет запросы.
2. Создать третью запись `Демо offline новая`.
3. Изменить сумму у `Демо offline изменить`.
4. Удалить `Демо offline удалить`.
5. Показать изменённый список, признаки неотправленных изменений и ненулевой счётчик очереди. Точное число элементов не фиксировать: очередь может объединять последовательные правки.
6. В браузере обновить список. Сервер пока содержит прежние данные.
7. Полностью закрыть и заново открыть приложение. Offline-режим, локальные изменения и очередь должны сохраниться.
8. Выключить offline. При необходимости выбрать «Синхронизировать» в верхнем меню.
9. Дождаться нулевой очереди. Обновить браузер и проверить все три операции.

Дополнительно показать **реальный сетевой сбой**: при выключенном переключателе offline остановить сервер в терминале A через Ctrl+C, попробовать синхронизацию. Должна появиться ошибка, сохранённый список остаётся доступным. Запустить сервер снова и синхронизировать. Альтернатива — отключить Wi-Fi телефона, если этим действительно прерывается маршрут к API.

Автоматическая попытка выполняется примерно раз в 30 секунд, пока приложение исполняется. Это не системная фоновая служба. После неопределённого исхода запроса повтор использует прежний Idempotency-Key, чтобы не создать дубль.

## 7. Показать конфликт двух изменений

1. Онлайн создать отдельный расход `Демо конфликт` и синхронизировать.
2. На телефоне включить offline и изменить комментарий на `Изменено на телефоне`.
3. В браузере под тем же `demo` изменить **ту же запись**: комментарий `Изменено в браузере`.
4. На телефоне выключить offline и синхронизировать.
5. Показать блок «Конфликт изменений» с локальной и серверной версиями.
6. Нажать «Принять серверную»: на телефоне должен остаться вариант браузера, конфликт исчезает.
7. Повторить конфликт и выбрать «Сохранить локальную»: после синхронизации браузер должен показать вариант телефона.

Смысл: версия записи/If-Match предотвращает незаметную перезапись чужой правки. Если вместо редактирования запись была удалена сервером, сохранение локального варианта создаст новый UUID.

## 8. Показать JWT, кэширование и ошибки через curl

Следующие блоки выполнить **в одном терминале**. Они читают данные; единственный POST с плохими полями не должен создать запись.

```bash
cd ~/Unik/web_mobile_unik/lab2
LAB2_URL=https://192.168.0.104:8443
LAB2_CERT=certificates/server.crt
LAB2_TOKEN=$(curl -fsS --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo","password":"demo12345"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')
test -n "$LAB2_TOKEN" && echo 'JWT получен'
curl -i --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/expenses" \
  -H "Authorization: Bearer $LAB2_TOKEN" \
  -H 'Accept: application/json' -A 'Lab2-Demo/1.0'
```

Показать 200, `Content-Type`, `ETag`, `Cache-Control`, `Last-Modified` и `Vary`. Host формируется curl из URL, Accept задаёт желаемый формат, User-Agent — имя клиента. JWT в публичный отчёт не копировать.

Для условного GET сохранить заголовки во временный файл:

```bash
LAB2_HEADERS=$(mktemp)
curl -fsS --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/expenses" \
  -H "Authorization: Bearer $LAB2_TOKEN" -D "$LAB2_HEADERS" -o /dev/null
LAB2_ETAG=$(awk 'tolower($1)=="etag:" {sub(/\r$/, "", $2); print $2}' "$LAB2_HEADERS")
curl -i --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/expenses" \
  -H "Authorization: Bearer $LAB2_TOKEN" -H "If-None-Match: $LAB2_ETAG"
```

Если список между запросами не изменялся, ожидается **304 без тела**. После изменения расхода в браузере повторить последний curl со старым ETag: ожидается 200 и новый снимок. `private, no-cache` разрешает хранить приватный кэш, но требует проверки актуальности перед повторным использованием.

Ошибки:

```bash
curl -i --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/expenses"
curl -i --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo","password":"wrong"}'
curl -i --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/expenses/00000000-0000-0000-0000-000000000000" \
  -H "Authorization: Bearer $LAB2_TOKEN"
curl -i --cacert "$LAB2_CERT" "$LAB2_URL/api/v1/expenses" \
  -H "Authorization: Bearer $LAB2_TOKEN" -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: lab2-demo-invalid' -d '{}'
```

По порядку ожидаются **401, 401, 404, 400**. Для 403 войти в браузере как `viewer` / `demo12345` и попробовать создать расход: аккаунт имеет только право чтения, его список отделён от `demo`.

Не вызывать 500 искусственной порчей рабочей БД. Показать обработчик 500 в `backend/app/main.py`, обработку ошибок в `client/src/apiclient.cpp` и тесты. Остановка сервера создаёт сетевую ошибку, а не HTTP 500.

## 10. Диагностика и завершение

| Симптом | Что сделать |
|---|---|
| Таймаут входа | Проверить IP, порт 8443, запуск сервера и доступность health с телефона |
| Ошибка сертификата | Проверить SAN, срок, путь к сертификату ЛР2 и совпадение сертификата сервера с RPM |
| «Войти» недоступна | Выключить offline, дождаться завершения операции |
| Нет записи из браузера | Проверить одинаковые URL/аккаунт, выполнить синхронизацию; у ЛР2 нет WSS-push |
| Изменения остаются в очереди | Проверить offline, сеть, сессию и блок конфликта; не удалять SQLite |
| Изменение временно заблокировано | Сначала завершить повтор операции с неизвестным исходом, затем редактировать |
| Виден только прежний значок «Расходы» | Установить отдельный пакет `com.example.expenseslab2` |

Удалить через интерфейс только свои записи с префиксом `Демо`, синхронизировать, убедиться в нулевой очереди и выключенном offline. Остановить сервер через Ctrl+C, если он больше не нужен. Не удалять пользовательскую БД и токены ради очистки демонстрационных записей.

Полный показ завершён, когда продемонстрированы HTTPS и заголовки, CRUD в обоих браузерах и на телефоне, сохранение кэша/сессии, offline CRUD после перезапуска, синхронизация, конфликт и понятные ошибки. Снимки экрана телефона не делать; использовать живой показ и терминальные результаты.
