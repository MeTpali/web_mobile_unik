# Результаты проверки лабораторной №3

Дата: 25 октября 2026 года.

## Сервер и инфраструктура

- Ubuntu 24.04, PostgreSQL 16, nginx 1.24.
- Два blue backend запущены как systemd-инстансы на 9101/9102; green подготовлена на 9201/9202. Все порты backend привязаны к loopback.
- nginx принимает HTTPS/WSS на 9443. `/ready` проверяет БД и слушатель уведомлений.
- Общие PostgreSQL, JWT-ключ и квитанции операций: авторизация и повтор мутаций не привязаны к одному процессу.
- Кластерные интеграционные тесты: **5 passed**. Проверены балансировка, общая авторизация, одновременный повтор POST, конфликтующие PATCH, межпроцессный push, изоляция пользователей, WSS-авторизация первым кадром и ETag.
- Реальный сценарий `exercise-cluster.py` отключает backend, переподключает WebSocket, переключает blue → green, останавливает старую группу и выполняет откат. Точные счётчики и последовательность экземпляров — в [cluster-validation.json](cluster-validation.json).
- В финальном полном испытании: **334 успешных HTTPS-запроса, 0 ошибок**, WebSocket прошёл blue-1 → blue-2 → green-1 → blue-1.
- Выбранная группа включается в автозапуск systemd. Перезагрузка всего ПК для проверки не выполнялась.

## Ручной сценарий защиты

1. Показать `systemctl status`, `/ready`, `/meta`, ответы с разными `X-Backend-ID`.
2. В приложении войти на `https://<IP-ПК>:9443`. Показать состояние push, обслуживающий REST-backend и счётчик уведомлений.
3. В браузере изменить расход под тем же аккаунтом; показать обновление списка телефона без ручной синхронизации.
4. Остановить один backend. Продолжить чтение/изменение данных через балансировщик.
5. Включить offline, изменить данные, восстановить связь и синхронизировать.
6. Запустить монитор и переключить green. Показать версию 2 и новую функцию summary; остановить blue.
7. Продемонстрировать восстановление WebSocket и новый push. Выполнить откат на blue.
8. Показать проверенную подпись RPM и установленную версию приложения.

## Практические ограничения

- nginx, PostgreSQL и сам ПК остаются общими точками отказа. Проверяется отказ backend-процессов.
- При остановке старого backend WebSocket переподключается; непрерывность HTTP проверяется отдельно. Открытое соединение не переносится между процессами.
- LISTEN/NOTIFY не является долговечным журналом. После переподключения клиент выполняет REST-синхронизацию.
- Для старого Qt выбран совместимый transport Uvicorn с отключённым сжатием кадров. Зафиксированная версия Uvicorn поддерживает этот режим, но отмечает его как deprecated; обновление зависимостей требует повторной проверки на телефоне.
- PSDK rpmlint сообщает о неочищенных символах и `no-changelogname-tag`; сборка, подпись и установка прошли. Магазинная валидация не заявляется выполненной.
- Имя `sign_package` из задания представлено явной обёрткой `tools/sign_package.sh` над штатным `rpmsign-external` установленного SDK.
